# 上游透传策略与成本智能路由 — 需求规格（整理稿）

> 本文档由用户的非专业化叙述整理而来，作为实施计划的输入规格。
> 日期：2026-08-18 · 状态：待实施

---

## 1. 业务场景

运营者将 Aether（下称 AE）**作为格式转换网关**（而非反向代理）接入上游：

```
下游客户端 → AE（格式转换 + 计量 + 路由）→ NewAPI（OpenAI 兼容，全透传）→ 账号反代 → Gemini 官方
```

- 上游计费方式：**按次收费 + 按量收费**混合。
- 上游 NewAPI 开启全透传，因此上游的原始返回形态会直接到达 AE。
- 关键经济约束：**上游按次计费时，AE 的每一次自动重试都是真金白银**；上游对"被风控拦截的空响应"照样扣费。

## 2. 现状行为（问题陈述）

| # | 上游实际返回 | AE 当前行为 | 问题 |
|---|---|---|---|
| 1 | 正常响应 | 正常转发给下游 | 无 |
| 2 | 500 / 502 / 503 | 判定错误并自动重试 | 对按次计费上游，重试放大成本；重试结果不变时纯属浪费 |
| 3 | 400 等 4xx | 网关自动重试 | 4xx 是请求结构性问题，重试必然重复失败，且每次重试都消耗按次计费额度 |
| 4 | HTTP 200 但内容为空（Gemini 官方风控拦截，即"回空"） | 网关判定为错误返回，主动重试；重试仍失败则向下游返回 **AE 自己的 503** | 上游照常扣费，但 AE 把空响应吞掉并对下游报 503——**损失由运营者独自承担**（下游不付费，上游已扣费） |

## 3. 功能需求

### F1 上游透传与重试策略（核心诉求）

**作用范围**：可对某一个提供商（Provider）配置；若可行，支持按 Key、按 Model 覆盖（三者至少支持其一，优先 Provider 级 + Model 级覆盖）。

- **F1.1 完全透传模式（Full Passthrough）**
  上游返回什么，AE 原封不动转发给下游：状态码、响应头、响应体（含错误体）一字不改；不做格式转换、不做错误拦截、不做自动重试。

- **F1.2 限额重试 + 错误透传（Capped Retry then Passthrough）**
  自动重试最多 N 次（N 可配，如 2）；重试耗尽后，将**上游的原始错误**（状态码 + 错误体）直接透传给下游，而不是替换成 AE 自己的 503。（现有机制是重试耗尽后返回 AE 的 503，需改为可配置。）

- **F1.3 回空策略（Empty-Response Policy，针对 Gemini 风控）**
  检测到"200 但回空"时可配置处理流程，目标模板：
  1. 自动重试 1 次（次数可配，可为 0）；
  2. 重试仍回空时，**把空响应作为正常 200 原样透传给下游**，让下游承担"谷歌官方回空但正常扣费"的后果；
  3. 而不是 AE 拦截空响应并返回 503（现状：损失由运营者承担）。

- **默认行为保持不变**：未开启上述模式的提供商维持现有重试/503 行为，向后兼容。

### F2 错误诊断与取证

- **F2.1 回空取证**：回空发生时持久化保存——下游请求头、下游请求体、上游状态码、上游错误码与附加信息、命中的提供商/Key/模型、下游用户标识。
- **F2.2 4xx 取证 + AI 摘要**：对 400 类结构性错误，保存上游返回体与上游错误原文；提供 **AI 摘要**（用一段话总结错误原因）；同时可获取完整的原始 JSON。
- **F2.3 精准日志检索**：提供按下游用户 / Key / 错误类型 / 时间范围精准查询的能力，并保留响应体，用于定位并封禁特定下游用户的破限（越狱/滥用）行为。

### F3 成本分层智能路由（对全部模型生效）

- 对每个模型可配置**上下文长度阈值**：
  - 预估上下文 **< 阈值** → 路由到**按量计费**上游；
  - 预估上下文 **≥ 阈值** → 路由到**按次计费**上游。
- **利润优先**：成本路由的优先级高于会话粘性；但被路由到按量上游的请求仍需保持**会话粘性与缓存粘性**（复用已有的 sticky session 机制）。
- 对所有模型通用（以模型为配置单位，通配/默认策略兜底）。
- 上下文长度采用估算（请求体字符/消息数启发式），不要求精确分词。

### F4 架构约束

- 尽可能做成**可插拔模块**（运行时配置开关、可选组件），让运营者可自由装卸。
- **硬性能力必须进入核心源码**（常驻编译，不依赖外挂补丁）。
- 遵循代码库既有约定：配置存于 `providers.config` / `models.config` JSON 命名空间（参照 `responses_websocket` 的落地模板），不引入与架构测试冲突的结构。

## 4. 非目标（本期不做）

- 不改变 NewAPI / 账号反代侧的行为。
- 不做精确 tokenizer（估算即可）。
- 不重写现有 WebSocket Responses 通道（本次场景为 HTTP 转换链路）。
- Key 级独立配置若需新增数据库列，列为后续工作（Provider + Model 两级已覆盖场景）。

## 5. 验收标准（摘要）

1. 对开启"完全透传"的提供商：上游 4xx/5xx/回空均原样到达下游，AE 不产生任何重试。
2. 对开启"限额重试 + 透传"（N=2）的提供商：最多 2 次重试后，下游收到上游原始错误而非 AE 503。
3. 对开启"回空透传"（重试 1 次）的提供商：回空重试 1 次后仍为空时，下游收到 200 空响应；该事件写入诊断表。
4. 诊断接口可按用户/错误类型列出事件，并返回请求头、请求体、上游错误 JSON；4xx 事件可生成并缓存 AI 摘要。
5. 配置了成本路由的模型：短上下文请求命中按量提供商、长上下文命中按次提供商；按量侧保持会话粘性；利润优先级高于粘性。
6. 未配置新选项的提供商行为与现状完全一致（回归无变化）。
